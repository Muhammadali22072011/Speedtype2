## МЕТОД — три прохода, строго по порядку

### Проход A. Инвентаризация

Составь два списка и положи их в `audit/inventory.md`:

- **Список М** — всё, что есть у monkeytype: каждая страница, каждый экран,
  каждая модалка, каждый элемент управления, каждая настройка, каждый режим,
  каждое состояние (пусто / загрузка / ошибка / нет сети / не авторизован).
- **Список S** — то же самое у нас.

Списки строятся из кода, а не из README. README врёт — это уже проверено
(см. раздел «Известные расхождения»).

Для настроек список делай машинно: их `config-schema` против нашего
`frontend/src/state/config-spec.ts`. Выведи три множества: только у них,
только у нас, у обоих. По каждому общему — сверь тип, набор значений и
значение по умолчанию.

### Проход B. Сверка

Для каждой строки списка проставь один из вердиктов:

| вердикт | значение |
|---|---|
| `ЕСТЬ` | реализовано и ведёт себя так же |
| `ЧАСТИЧНО` | есть, но отличается — обязательно опиши, чем именно |
| `ЗАГЛУШКА` | элемент нарисован, логики нет (`done: false` и подобное) |
| `НЕТ` | отсутствует |
| `ЛИШНЕЕ` | есть у нас, нет у них — это не ошибка, но отметь |

`ЧАСТИЧНО` без описания отличия — недопустимый ответ. Пиши конкретно:
«отступ 1rem против 0.5rem», «нет анимации при переключении», «порядок
колонок другой», а не «немного отличается».

### Проход C. Реализация

Чини найденное. Порядок: сперва то, что видно на главной странице,
затем настройки, затем аккаунт, затем остальное. Внутри каждой группы —
сперва сломанное, потом отсутствующее, потом косметика.

## ЧЕК-ЛИСТ ПО ДИЗАЙНУ

Это отдельный проход. Функция может работать и при этом выглядеть чужой.

**Переменные темы.** Их семь: `--bg-color`, `--main-color`, `--caret-color`,
`--sub-color`, `--sub-alt-color`, `--text-color`, `--error-color`,
`--error-extra-color`, `--colorful-error-color`. Сверь полный список с их
css. Если у нас переменной нет, а в их темах она используется — 52 файла
тем работают не полностью. Проверь буквально: открой их `serika_dark.css`
и наш, сравни построчно.

**Типографика.** Гарнитуры (у них Lexend Deca по умолчанию + ~30 шрифтов на
выбор), размеры в rem, межстрочный, насыщенность, регистр. У них весь
интерфейс в нижнем регистре — проверь, что у нас нигде не проскакивает
заглавная.

**Сетка и отступы.** Максимальная ширина контента, отступы по краям,
расстояния между блоками, выравнивание шапки и футера по одной сетке.

**Скругления, тени, границы.** У них скругления заданы одной переменной.

**Анимации и переходы.** Длительность и функция сглаживания у: наведения на
кнопку, переключения настройки, появления результата, прокрутки строк,
каретки, открытия командной строки, уведомлений. Сверь числа, а не
ощущение. `transition: .125s` и `.25s` — разный интерфейс.

**Состояния.** Обычное, наведение, нажатие, фокус с клавиатуры, отключено,
активно. У нас, вероятно, нет `:focus-visible` — проверь.

**Адаптив.** Их брейкпоинты против наших. У нас в `monkeytype.css` 682
строки — посчитай, сколько там `@media`. Если ноль, это дыра.

**Доступность.** `aria-label` у иконочных кнопок, `prefers-reduced-motion`,
контраст в светлых темах, навигация по `tab`.

**Метод сверки визуального.** Не сравнивай по памяти. Открой обе страницы
браузером (инструменты `mcp__Claude_Browser__*`), поставь одинаковый размер
окна и одинаковую тему `serika_dark`, сделай скриншоты одних и тех же
экранов и сравни. Для точных значений — `getComputedStyle` через
`javascript_tool` на их сайте и на нашем.

   Это значит, что каждая шестая настройка на странице — обманка.

## ПРАВИЛА, КОТОРЫЕ НЕЛЬЗЯ НАРУШАТЬ

- **Метрики считает сервер.** Клиент шлёт только `correct_chars`,
  `incorrect_chars`, `duration` и посекундные замеры wpm. Всё остальное —
  `backend/app/services/metrics.py`. Формулы в `frontend/src/core/metrics.ts`
  дублируют серверные только ради совпадения цифр на экране. Меняешь формулу —
  меняй в обоих местах одновременно.
- В прошлой версии `consistency` был `Math.random()`. Есть тесты, которые это
  стерегут. **Не ослабляй их.**
- **Не переименовывай классы разметки теста**: `#words`, `.word`, `<letter>`,
  `#caret`. На них держатся 52 файла тем monkeytype.
- **Не ставь пакеты в глобальный Python.** Только `backend/.venv`. В глобальном
  живёт aiogram, ему нужен `pydantic<2.10`.
- **Vite обязан проксировать и `/api`, и `/static`, и `ws: true`.** Без второго
  правила css темы приходит пустым — Vite отдаёт свой `index.html`, браузер
  парсит его как css и получает ноль правил. Ломается молча.
- **Heredoc в bash ломается об апострофы** в русских текстах и в CSS.
  Файлы с кавычками пиши инструментом Write.
- Новая настройка — строка в `config-spec.ts` плюс ключ и значение по
  умолчанию в `settings.ts` (интерфейс `Settings` и объект `DEFAULTS`).
  `done: true` ставится только после того, как написана логика.
- Новый funbox — запись в `FUNBOXES` в `core/funbox.ts`. Виды: `text`
  (пиши `transform`), `css` (`hasCss: true` + файл в `static/funbox/`),
  `behavior` (обрабатывается в `pages/test.ts`). Режимы, подменяющие
  генерацию текста целиком, помечай `generator: true`.
- Комнаты гонок живут в памяти процесса. Один воркер. Не притворяйся, что
  это масштабируется.
- Интерфейс на русском. Новые подписи пиши по-русски, в нижнем регистре,
  коротко — как в существующих файлах.
