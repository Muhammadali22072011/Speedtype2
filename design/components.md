# Компоненты

Всё видно живьём на [/styleguide](http://127.0.0.1:5173/styleguide) — там
каждый компонент нарисован во всех состояниях на текущей теме. Страница
служебная, из поиска закрыта.

Шесть состояний обязательны у каждого: **обычное · наведение · нажатие ·
фокус с клавиатуры · отключено · активное**. До этой работы `:active`
не было вовсе, `:focus-visible` стоял на одной кнопке, `disabled` — на одной.

Наведение, нажатие и фокус можно показать принудительно классами
`is-hover`, `is-press`, `is-focus`. Они перечислены в css через запятую
рядом с настоящими псевдоклассами — не отдельными правилами, поэтому
оформление у них общее и разъехаться не может.

## Кнопки

| компонент | класс | где стоит | состояния |
|---|---|---|---|
| основная | `.button` | формы, экран результата, списки выбора | все шесть + `.danger` |
| текстовая | `.textButton` | футер, панель режимов, индикатор темы | все шесть |
| иконочная | `.button.iconButton` | рестарт, действия в шапке списка | все шесть |
| опасная | `.button.danger` | удаление результатов | краснеет только под курсором |
| пункт меню | `[data-nav-item]` | шапка | все шесть |
| перезапуск теста | `#restartButton` | под словами | фокус показывает не кольцом, а обратной заливкой: кнопка лежит на словах, и кольцо на ней теряется |

`.textButton` — имя из monkeytype, его ждут три темы (`chaos_theory`,
`phantom`, `rainbow_trail`, `solarized_osaka`).

`[data-nav-item]` и `.textButton` читают крючки темы:
`var(--themable-button-text, var(--nav-fg))`. 26 файлов тем из 52 задают
эти переменные на конкретных пунктах меню — без чтения крючков половина
цветных меню не работала. Подставляются они в правиле компонента, а не
на `:root`: переменная, объявленная на корне, подставится один раз на корне,
и правило темы для одного пункта до неё не дотянется.

Проверено на `chaos_theory`: пункт «настройки» получает `rgb(255, 88, 105)`,
«тест» — `rgb(171, 146, 225)`, то есть тема красит пункты по отдельности.

## Поля ввода

| компонент | класс | состояния |
|---|---|---|
| текстовое поле | `.input` | обычное, наведение, фокус, ошибка (`aria-invalid`), отключено |
| числовое, текстовая область | `.setNumber`, `.setText` | то же |
| поле теста | `#wordsInput` | скрыто намеренно: ловит нажатия, признак фокуса — каретка в словах |

## Обратная связь

| компонент | класс | где стоит |
|---|---|---|
| уведомление | `.notification` в `#notifications` | угол экрана, поверх модалок; API — `ui/notify.ts` |
| подсказка-облачко | `[aria-label][data-balloon-pos]` | иконочные кнопки; ждёт одна тема |
| значок | `.badge`, `.badge.accent`, `.badge.danger` | пометки у строк |
| полоса прогресса | `.progressBar` + `.fill` | таймер теста, дорожка гонки |
| пусто | `.emptyState` | список результатов, лидерборд |
| грузится | `.loadingState`, `.spinner` | лидерборд, история |
| сломалось | `.errorState` | ошибка запроса |
| клавиша | `<kbd>` | подсказки клавиш, командная строка; ждут две темы |

Уведомление объявляет себя `role="status"` и `aria-live="polite"`: экранный
диктор прочитает текст, не уводя фокус из поля ввода. Живёт три секунды,
ошибка — шесть, крестик закрывает досрочно.

## Вход и регистрация

Своя разметка, классы держатся в `styles/auth.css` и никуда больше не ходят —
общих классов под одну страницу не заводим.

| компонент | класс | что делает |
|---|---|---|
| колонка формы | `.authPage` + `.authForm` | центрирует форму по экрану, ширина 20rem — их `sm:w-80` |
| заголовок | `.authTitle` | иконка и текст кеглем основного текста, цвет приглушённый — их `H3` |
| поле с подписью | `.authField`, `.authLabel`, `.authHint` | метка обёрнута вокруг `input`, связь без id |
| ошибка | `.authError` | место занято всегда, первая буква приводится к нижнему регистру |
| переход между формами | `.authSwitch` | «нет аккаунта? зарегистрироваться» |

Кнопка и поле — общие `.button` и `.input`. До этой правки в разметке стояли
`.btn` и `.muted`, которых в проекте нет ни одного правила: кнопка входа была
не «плохо оформлена», а не оформлена вовсе.

## Страницы

Классы `.pageSettings`, `.pageAccount`, `.pageAbout` роутер выводит из адреса
(`router.ts`) — их ждут файлы тем. Класс `.page` на том же контейнере нужен
funbox `space_balls`, который наклоняет `main .page`.

Текстовые страницы дополнительно ставят себе `.textPage`: под каждый новый
адрес заводить правило руками не хочется, а оформление у них общее.

## Что осталось не приведённым к системе

- **Гонка** рисует слова своим кодом, настройки отображения к ней не
  применяются (замеры 536–538). Это не про токены, а про общий рендер
  теста — работа отдельная.
- **Экран результата** пользуется собственной сеткой `#result .stats`;
  под общий `.card` не переводился, потому что у него другая задача.
- **Панель режимов** осталась одной карточкой, у monkeytype их три
  (замер 44). Это уровень 2 плана из `audit/gaps.md`, не дизайн-система.
