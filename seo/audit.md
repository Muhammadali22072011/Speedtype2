# SEO-аудит Speedtype 2 — что было

Дата замера: 20 августа 2026. Домен согласован: `speedtype.izzatullaev.uz`,
канонический вид — `https://speedtype.izzatullaev.uz` без `www`.

Всё ниже проверено на этой машине командами, а не взято из общих соображений.
Где проверить не удалось — так и написано.

## Как снимались замеры

Собранный `dist` подан через временный статический сервер из scratchpad
(`serve-dist.mjs`), который проксирует `/api` и `/static` на живой бэкенд
на порту 8000. Это ближе к проду, чем `vite dev`: тот отдаёт неминифицированные
модули по одному и меряет совсем другое.

Lighthouse 13.4.1, headless Chrome, мобильный и настольный профили.
Пакет поставлен во временную папку, в зависимости проекта не добавлен.

**Оговорка, важная для честности цифр.** Временный сервер не ставит
`Cache-Control` — поэтому аудит `cache-insight` в отчёте ругается на мой
стенд, а не на проект. Заголовки настоящего бэкенда проверены отдельно
`curl`-ом, результат ниже в таблице.

### Про «SEO 100» — это не то, чем кажется

Главный вывод аудита: **оценка SEO 100 у Lighthouse ничего не говорит
о том, найдут ли сайт.** Он проверил, что `<title>` есть, `description`
есть, `viewport` есть и страница не закрыта от индексации. Он не проверяет,
есть ли на странице хоть что-нибудь, кроме пустого `<div>`.

Смотреть надо на то, что аудиты пропущены, а не пройдены:

| аудит | результат | что это значит |
|---|---|---|
| `canonical` | `score = null` | тега нет вовсе, поэтому проверка пропущена — не «пройдена» |
| `structured-data` | `score = null` | разметки нет, проверять нечего |
| `hreflang` | `score = 1` | проходит именно потому, что тегов нет |
| `is-crawlable` | `score = 1` | значит только «нет запрета», `robots.txt` при этом отсутствует |

Иначе говоря, три из четырёх «зелёных» пунктов зелены оттого, что проверять
нечего. Ориентироваться на эту сотню нельзя.

### Размер сборки

```
dist/index.html                   0.86 КБ  (gzip 0.50 КБ)
dist/assets/index-*.css          16.12 КБ  (gzip 3.71 КБ)
dist/assets/index-*.js           85.50 КБ  (gzip 27.81 КБ)
dist/assets/index-*.js.map      224.79 КБ  ← уезжает в прод
```

Один чанк на всё приложение. Lighthouse: **35 КБ из 80 КБ (44%) кода
на главной не используется** — это страницы гонок, настроек, профиля
и авторизации, которые грузятся всем и всегда.

### Что грузится до первой отрисовки

Waterfall с мобильного прогона, по порядку:

```
   0 мс   документ
   8 мс   fonts.googleapis.com/css2  ← блокирует отрисовку
   9 мс   index.js, index.css
 457 мс   /api/themes           ← 62 КБ, ждём его
 463 мс     …ответ получен
 466 мс   /api/words/english    ← стартует только теперь
 715 мс   /favicon.ico          ← 404
```

Это подтверждает цифрами: запрос слов **не начинается**, пока не пришли
62 КБ списка тем. Зависимость последовательная, потому что в
[main.ts:97](frontend/src/main.ts:97) роутер запускается внутри `.finally()`
у `applyThemeByName`, а тот ждёт `fetch("/api/themes")`
([themes.ts:20](frontend/src/state/themes.ts:20)).

Аудит `render-blocking-insight`: **score 0, экономия 1720 мс**, из них
996 мс — css шрифта с `fonts.googleapis.com`, 303 мс — собственный css.

### Сырой html, как его видит краулер

```bash
curl -s http://127.0.0.1:4173/
```

Возвращает 20 строк: `<title>speedtype</title>`, одно описание, теги шрифта,
`<div id="app"></div>`. Ни заголовка страницы, ни текста, ни `og:`.
Скребки превью Telegram, WhatsApp и Discord js не выполняют — они увидят
ровно это.

### Ответы бэкенда на клиентские маршруты

```bash
for r in / /race /leaderboard /profile /settings /login /register /нет-такой; do curl -o /dev/null -w "%{http_code} $r\n" -s http://127.0.0.1:8000$r; done
```

```
404 /            404 /race        404 /leaderboard   404 /profile
404 /settings    404 /login       404 /register      404 /нет-такой
```

**Все семь маршрутов, включая главную, отдают 404.** Бэкенд не умеет отдавать
`index.html` вообще. Сейчас это не мешает только потому, что в разработке
страницы раздаёт Vite.

## Итог

Ломается всё в одном месте: **бэкенд не отдаёт `index.html`, а `index.html`
пуст**. Первое означает, что сайт в проде вообще не откроется по прямой
ссылке. Второе — что даже когда откроется, краулер и скребок превью увидят
пустой `div`.

Всё остальное — заголовки, карта сайта, разметка, скорость — имеет смысл
только после этих двух правок.

Отдельно стоит сказать вслух: техника делает сайт индексируемым, но переходы
приносит текст. Семь интерактивных маршрутов без единой страницы с текстом —
это одна страница в индексе, как ни размечай.
