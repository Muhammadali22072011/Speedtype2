# SEO-план Speedtype 2 — что делать

Отсортировано по паре «эффект × стоимость». Сверху то, без чего не работает
ничего; снизу то, что можно не делать вовсе.

Домен: `speedtype.izzatullaev.uz`. Канон — `https://speedtype.izzatullaev.uz`,
без `www`, по https. **Адрес живёт в одном месте** — поле `site_url`
в `backend/app/core/config.py`, читается из окружения. Поменять домен =
поменять одну переменную, а не тридцать строк.

---

## Развилка, которую надо назвать вслух

Из четырёх способов отдавать html выбран **вариант C: FastAPI подставляет
`<head>` под маршрут**. Причины ровно две, и обе практические:

- Node в проде не нужен — бэкенд уже раздаёт статику;
- это единственный вариант, который чинит превью в Telegram: скребки
  не выполняют js, им нужен готовый `og:` в ответе сервера.

**Чего вариант C не даёт, и это надо знать заранее.** Мета-теги
подставляются только когда html отдаёт бэкенд. В `vite dev` страницу
раздаёт Vite из `frontend/index.html`, и никаких подставленных тегов там
не будет. Это не поломка — это разные пути кода. Поэтому:

- в dev заголовок меняет `router.ts` через `document.title`;
- проверять мета-теги надо **только** на собранном `dist`, поданном
  через бэкенд;
- в чек-лист проверок войдут оба режима.

## Этап 1. Catch-all и честный 404

Без этого сайт в проде не открывается по прямой ссылке — сейчас все семь
маршрутов, включая главную, отдают 404.

| | |
|---|---|
| файлы | `backend/app/main.py`, `backend/app/core/config.py`, новый `backend/app/core/seo.py` |
| объём | ~90 строк |
| риск | **средний**: неверный порядок роутов перехватит `/api` |

Что делаю:

1. В `config.py` — поля `site_url` и `frontend_dist` (путь к собранному
   `dist`, по умолчанию `../frontend/dist`).
2. В `seo.py` — словарь маршрут → мета-данные. Он же источник правды
   для карты сайта, `noindex` и заголовков.
3. В `main.py` — роут `GET /{path:path}` **последним**, после всех
   `include_router` и `mount`.
4. Порядок проверок внутри: известный маршрут → `index.html` с
   подставленным `<head>` и кодом 200; неизвестный → тот же html, но код
   **404**. SPA отрисует свою страницу «такой страницы нет», а поиск
   получит честный код.
5. `/api/*`, `/static/*`, `/assets/*` до catch-all не доходят — их
   перехватывают роутеры и mount, зарегистрированные раньше.
6. Если `dist` не собран — понятный текст с подсказкой `npm run build`,
   а не пятисотка.

Отдельно: `mount("/assets")` на `dist/assets` с годовым `Cache-Control` —
имена файлов там с хешем, инвалидация не нужна.

**Проверка:** `curl` по каждому маршруту с собранным `dist`; коды 200/404
в таблицу.

## Этап 2. Мета-теги по маршрутам

| | |
|---|---|
| файлы | `backend/app/core/seo.py`, `frontend/src/router.ts`, `frontend/index.html` |
| объём | ~120 строк, из них половина — тексты |
| риск | низкий |

Для каждого из семи маршрутов: `title` до 60 символов, `description`
140–160, `canonical`, `robots`. Черновик из твоего промпта беру за основу,
но правлю — в нём часть заголовков длиннее 60 символов:

| маршрут | title | длина | robots |
|---|---|---|---|
| `/` | Тест скорости печати онлайн — Speedtype | 39 | index |
| `/leaderboard` | Рейтинг скорости печати — Speedtype | 35 | index |
| `/race` | Гонки по печати с друзьями — Speedtype | 38 | index |
| `/settings` | Настройки — Speedtype | 21 | **noindex** |
| `/profile` | Профиль — Speedtype | 19 | **noindex** |
| `/login` | Вход — Speedtype | 16 | **noindex** |
| `/register` | Регистрация — Speedtype | 22 | **noindex** |

Плюс в `router.ts` — обновление `document.title` и `description` при
переходах внутри SPA. Список заголовков на клиенте держать отдельно
нельзя (разъедется с сервером), поэтому отдаю его одним маленьким
эндпоинтом либо инлайню в html как `<script type="application/json">`.
Склоняюсь ко второму: лишний запрос на первом экране не нужен.

## Этап 3. `robots.txt`, `sitemap.xml`, canonical

| | |
|---|---|
| файлы | `backend/app/api/routes/seo.py` (новый) |
| объём | ~50 строк |
| риск | низкий |

Оба генерируются из словаря маршрутов, а не пишутся руками — иначе при
добавлении страницы карта устареет молча.

- `robots.txt`: разрешить всё, закрыть `/api/`, `/profile`, `/settings`,
  `/login`, `/register`, указать адрес карты.
- `sitemap.xml`: только маршруты с `index`, абсолютные адреса.
- `canonical`: подставляется в `<head>` из этапа 1, `?param` и `/` на
  конце схлопываются в один вид.

Плюс редирект `/путь/` → `/путь` (301) на бэкенде.

## Этап 7. Скорость

| | |
|---|---|
| файлы | `index.html`, `main.ts`, `themes.ts`, `vite.config.ts`, `main.py` |
| объём | ~80 строк |
| риск | **средний**: трогает запуск приложения и загрузку темы |

По убыванию эффекта, все цифры из замеров:

1. **Шрифт — 996 мс блокировки.** Кладу Roboto Mono локально (woff2,
   три начертания) и убираю зависимость от `fonts.googleapis.com`.
   Заодно уходит сторонний домен и два `preconnect`.
2. **`/api/themes` (62 КБ) держит запуск роутера.** Семь переменных
   `serika_dark` встраиваю в `index.html`, роутер стартует сразу,
   список тем грузится, когда открыли пикер. По waterfall это
   развязывает и запрос слов — сейчас он ждёт окончания тем.
3. **Разбиение сборки.** Динамические `import()` в `main.ts`:
   44% кода главной сейчас не используется (35 КБ из 80 КБ).
4. **`GZipMiddleware`** на бэкенде — одна строка, сейчас сжатия нет вовсе.
5. **`Cache-Control`** на `/static` — сейчас только `etag`.
6. **`sourcemap` выключаю** — решено, минус 225 КБ из прода.

Риск здесь настоящий: пункты 1–3 трогают порядок запуска. После каждого —
`npm run typecheck && npm test` и глазами проверить, что тема не мигает.

## Этап 8. Контентные страницы

Самый большой кусок и главный источник переходов. Техника делает сайт
индексируемым, но приходят люди на текст.

| | |
|---|---|
| файлы | новые страницы во фронтенде + маршруты + мета + карта сайта |
| объём | 5 страниц, ~1500 слов живого русского текста |
| риск | низкий технически, высокий по времени |

1. **`/guide`** «Как научиться печатать вслепую» — постановка рук,
   домашний ряд, упражнения по неделям, типичные ошибки. Разметка `HowTo`.
2. **`/norms`** «Какая скорость печати считается нормальной» — таблица
   по уровням. Частый запрос.
3. **`/faq`** — что такое wpm, чем отличается raw, как считаются accuracy
   и consistency. **Формулы беру из `backend/app/services/metrics.py`
   и объясняю по-человечески** — это честный уникальный текст, которого
   у конкурентов нет. Разметка `FAQPage`.
4. **`/about`** — чем отличается от monkeytype, что метрики считает сервер,
   и текст GPL-3.0 из `LICENSE-NOTICE.md`. Последнее не для SEO, а потому
   что при публикации это обязательно.
5. **«Как увеличить скорость печати»** — если после первых четырёх
   останутся силы; по смыслу это продолжение гайда.

Внутренние ссылки: из каждой страницы в тренажёр и обратно.

## Этап 9. Страницы под режимы — две-три, с живым текстом

**Решено:** делаю тест на русском и тест на узбекском, при возможности
третью. Условие остаётся жёстким: страницы должны **правда** отличаться
текстом, иначе это дублирующийся контент, за который понижают. Поэтому
берутся именно языковые — там есть что написать по делу (какие слова
в словаре, чем узбекская раскладка отличается, откуда взят словарь),
а не «тест на 60 секунд» и «тест на 1 минуту», которые отличались бы
одним числом.

Остальные — отдельным заходом, когда станет видно, что индексируется.

## Порядок и точки проверки

```
1 → catch-all и 404          curl по семи маршрутам, коды 200/404
2 → мета-теги                curl | grep title, description, canonical
3 → robots, sitemap          curl /robots.txt, /sitemap.xml
4 → og                       ссылка в Telegram
5 → иконки и манифест        глазами во вкладке
6 → JSON-LD                  валидатор Google Rich Results
7 → скорость                 Lighthouse до/после рядом
8 → контент                  ссылки, заголовки, разметка
```

После каждого этапа:

```bash
cd backend && .venv/Scripts/python -m pytest -q
```

```bash
cd frontend && npm run typecheck && npm test && npx vite build
```

И отдельно — то, что ломается молча: `dist`, поданный **через бэкенд**,
а не через `vite dev`. Мета-теги видны только там.

## Оценка эффекта — без обещаний

Что эти правки дают наверняка:

- сайт откроется по прямой ссылке (сейчас — нет);
- краулер увидит семь разных страниц вместо одной пустой;
- ссылка в Telegram покажет карточку вместо голого адреса;
- мобильный LCP улучшится — 996 мс блокировки шрифта и 62 КБ перед
  стартом роутера убираются измеримо.

Чего они не дают: позиций. Прямая конкуренция с monkeytype и typing.com
по запросу `typing test` не выигрывается — у них годы ссылочной массы.
Реальная цель — русские и узбекские запросы и длинный хвост, и туда
приходят через тексты этапа 8, а не через мета-теги.

Сколько страниц попадёт в индекс и когда — решает поиск. Замерим через
две недели после выкладки и запишем в `after.md` как есть.
