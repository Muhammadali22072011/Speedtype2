# Speedtype 2

Тренажёр слепой печати. Переписан с нуля: FastAPI на бэкенде, SPA на TypeScript
на фронтенде, дизайн — тема `serika_dark` из monkeytype.

## Что здесь по-другому

Прошлая версия была одним файлом `main.py` на 56 КБ и шаблоном `index.html`
на 132 КБ, внутри которого лежал весь тест. Плюс две реальные ошибки в расчётах:

| | было | стало |
|---|---|---|
| `consistency` | `Math.random() * 30 + 70` | коэффициент вариации посекундных замеров wpm |
| `wpm` | `введённые слова / время` | `(верные символы / 5) / минуты`, как в monkeytype |
| `accuracy` | доля от длины текста | доля верных нажатий от всех нажатий |
| кто считает | клиент, сервер верил на слово | сервер по сырым счётчикам |

Клиент присылает только `correct_chars`, `incorrect_chars`, `duration` и
посекундные замеры. Всё остальное считает сервер — иначе результат можно
прислать любой.

## Структура

```
backend/
  app/
    main.py              точка входа FastAPI
    core/config.py       настройки через pydantic-settings
    core/security.py     bcrypt + JWT
    db/session.py        engine и сессия SQLAlchemy 2.0
    db/seed.py           заливка языков из JSON
    data/languages/*.json    словари для первичного сида базы
    data/themes.json     187 тем, по десять переменных на каждую
    static/              источник правды по словам, цитатам, раскладкам,
                         звукам и css тем — файлы monkeytype как есть
    models/__init__.py   таблицы
    schemas/__init__.py  валидация запросов и ответов
    api/routes/          auth, results, leaderboard, text, race, assets
    services/metrics.py  формулы
    services/anticheat.py    проверка правдоподобности
  tests/                 29 тестов

frontend/
  src/
    core/engine.ts       движок теста, не знает про DOM
    core/metrics.ts      те же формулы для показа в реальном времени
    api/client.ts        обёртка над fetch
    router.ts            роутер на history API
    state/settings.ts    настройки в localStorage
    pages/               test, about, race, leaderboard, auth, profile, settings
    styles/monkeytype.css    разметка теста, шапка, кнопки, таблицы
    styles/modes.css     режимы отображения, клавиатура, настройки, модалки
    ui/format.ts         помощники отображения
```

Языки лежат в JSON, а не в коде: чтобы добавить язык, положите файл рядом
с `english.json` и запустите сид заново.

Темы — тоже данные. Тема это десять CSS-переменных в
`backend/app/data/themes.json`; клиент вставляет их тегом `<style>` в head,
а не inline на `<html>` — иначе css самой темы не смог бы их перекрыть.

## Запуск

Бэкенд (порт 8000):

```bash
cd backend && .venv/Scripts/python -m uvicorn app.main:app --reload
```

Фронтенд (порт 5173, ходит в бэкенд через прокси):

```bash
cd frontend && npm run dev
```

Документация API открывается сама: http://127.0.0.1:8000/docs

## Тесты

```bash
cd backend && .venv/Scripts/python -m pytest -q
```

```bash
cd frontend && npm test
```

## Данные из monkeytype

Из их репозитория взяты темы, словари, цитаты, раскладки и звуки —
см. [LICENSE-NOTICE.md](LICENSE-NOTICE.md). Коротко:

- **187 тем** — цвета в `backend/app/data/themes.json`, у 52 из них
  есть свой css с анимациями в `backend/app/static/themes/`
- **432 языка** в `backend/app/static/languages/`
- **87 наборов цитат**, **239 раскладок**, **26 звуков**

Разметка теста повторяет их: `#words` → `.word` → `<letter>`, отдельный
`#caret`. Поэтому файлы тем применяются как есть — `aurora.css` красит
каретку своей анимацией, ничего подкручивать не пришлось.

Проект использует код под GPL-3.0. Пока он лежит на вашем компьютере,
обязательств нет; при публикации исходники нужно открыть.

## Настройки

84 настройки в 8 группах. Список задан одним файлом —
`frontend/src/state/config-spec.ts`. Из него сами строятся и страница
настроек, и командная строка: добавить настройку значит дописать строку.

Сколько из них работает, страница настроек считает сама и пишет в шапке —
это не число из README, а `SETTINGS.filter(s => s.done).length`. Проверить
можно так:

```bash
grep -c "done: false" frontend/src/state/config-spec.ts
```

Нереализованные помечены `done: false` и показываются приглушёнными
с подписью «пока не работает». Полный разбор, чего именно не хватает
против monkeytype, — в [audit/report.md](audit/report.md); у них в схеме
94 ключа против наших 84.

## Командная строка

`ctrl+shift+p`, как в оригинале. 90 команд, поиск, стрелки, вложенные
списки значений. Собирается из той же схемы настроек.

## Funbox

44 режима трёх видов (у monkeytype их 48):

- **текстовые** — `backwards`, `rot13`, `morse`, `binary`, `hexadecimal`,
  `gibberish`, `ascii`, `leet`, `nospace`, `capitals` и другие;
- **визуальные** — `mirror`, `crt`, `nausea`, `earthquake`, `space_balls`,
  `read_ahead`; стили берутся из `static/funbox/*.css` monkeytype;
- **правила** — `plus_zero`…`plus_three`, `memory`, `no_quit`.

Режимы, подменяющие генерацию текста, взаимно исключаются — при выборе
нового предыдущий снимается сам.

## Механики

- режимы: время, слова, цитата
- пунктуация и цифры отдельными переключателями
- три видимые строки с прокруткой по мере набора
- живой wpm во время теста, панель настроек прячется при старте,
  шапка и футер гаснут, пока идёт набор
- `tab` — начать заново, `esc` — командная строка
- график скорости по секундам в результатах
- отметка личного рекорда
- слепой режим, плавная каретка

## Онлайн

Гонки на WebSocket: комната по коду из пяти символов, до 8 игроков,
у всех одинаковый текст, отсчёт 5 секунд, прогресс каждого едет полосой.

Комнаты живут в памяти процесса — для нескольких воркеров понадобится Redis.

## Клавиатура и звук

Клавиатура на экране рисуется по раскладке из 239 файлов monkeytype,
подсвечивает следующую клавишу и вспыхивает на нажатии. Четыре формы,
четыре стиля подписей, масштаб.

Звук нажатий — 21 набор по три сэмпла (чтобы подряд идущие клавиши
не звучали одинаково) и 4 набора звука ошибки.
